一面结论：岗位是 **网安工程师**，工作偏 **AI 应用层安全测试 + 方案设计**。

## 0. 二面怎么开口（70 秒）

面试官你好，上一轮后我把岗位理解成：对 **AI 应用全链路** 做安全测试和方案，不只是终端逆向。链路是数据集、训练微调、模型部署、推理服务。

我主线是生成模型水印：视觉语言模型和扩散音频。习惯是先定威胁（再分发、误触发、去除、提取），再把约束写进训练，再在微调、L2 结构化剪枝、压缩失真后做回归。所以对训练侧和推理侧「上线前要测什么」比较熟。应用层方案我会把鉴权做在数据权限、训练任务、工具适配器上，不写在系统提示里；训完必须安全回归才能注册部署。

密码学有 GlobeCom 一作和密文域竞赛。SFT/RLHF/DPO 是了解。终端逆向不是主项。希望二面把数据—训练—推理—部署这条安全门禁讲清楚。

**被问一面讲过什么：** 网安工程师不是测试执行岗；AI 应用层；工具权限必须做在代码里；水印形式上像后门、目标相反。

## 1. 二面主图（建议能画）

```
[数据集] 权限/版本/校验和/脱敏
    ↓ 训练 Job 只能挂有权的盘
[训练/微调] 镜像+命令审计，ckpt 隔离，密钥走 Secret
    ↓ 安全回归（能力 + 策略/水印 + 异常触发）
[制品注册] 过门禁才能进仓库，记下训练 ID 和指标
    ↓
[部署] 瘦推理镜像 + Deployment + readiness
    ↓
[推理] 登录、租户、分槽提示、RAG 过滤、工具鉴权、DLP、限流、水印出口
    ↓
[审计日志] 谁训的、谁调的、调了什么工具
```

口头：「应用层测试就是在每一跳验证：不该进的数据进不去，不该跑的训练跑不了，不该上线的权重上不了，不该调的工具调不了。」

## 2. 四段怎么测、怎么设计

### 2.1 数据集

| 测（失败标准） | 方案 |
| --- | --- |
| 无权限账号能读写训练桶/RAG 库 | 身份 + 租户强制，训练任务挂盘也要鉴权 |
| 语料里出现密钥、证件号仍被拿去训 | 入库扫描、脱敏、拒绝明文密钥 |
| 覆盖写入没有版本，出事无法回滚数据 | 数据集不可变版本 + 校验和 |
| RAG 文档能进训练、训练标注能被检索串库 | 训练区与检索区隔离 |

你没做过公司数据平台：说 **公开集实验，岗位上要补的是权限和溯源**。不要说自己扫过生产 PII。

### 2.2 训练 / 微调

| 测 | 方案 |
| --- | --- |
| 任意人能提交 GPU 任务、改命令读别人 ckpt | 任务提交鉴权；命令、镜像、PVC 进审计 |
| 基座来路不明 | 只允许仓库内已登记权重 |
| 日志把训练样本全文打出去 | 日志脱敏、禁止 dump batch |
| 微调后安全行为没了、或出现异常触发 | **发布门禁：主任务 + 安全/水印 + 干净样本误触发** |

接到你的实验：二次微调看 WSR；L2 通道剪枝看主任务和水印是否一起掉。对齐了解：再微调会遗忘拒答，同样要回归。  
音频冻声码器只训 adapter：方案上就是 **最小可训面**，少动基座，攻击面更小。

不要讲怎么做数据投毒。只说验证「未授权数据能否进 Job、训完行为是否仍符合策略」。

### 2.3 推理

| 测 | 方案 |
| --- | --- |
| 未登录打到 `/v1/chat` | 与业务同一套认证 |
| A 历史/知识库漏给 B | 租户在服务端注入检索 |
| 用户话或文档覆盖系统策略、骗调工具 | 分槽；工具二次鉴权；高风险人审 |
| 追问套出系统提示、密钥 | 秘密不进提示；输出 DLP |
| 高频刷接口 | 配额、审计（防提取滥用，不是去做提取） |

### 2.4 部署

| 测 | 方案 |
| --- | --- |
| 评测未过的 pt 能挂到线上 | 注册仓库门禁 |
| 训练大镜像直接当推理、启动慢还暴露训练依赖 | 训练/推理镜像分开 |
| 模型没 load 完就 200 | readiness |
| 出事不能回到上一版 | 版本绑定训练 ID，Service 切回 |

和平台岗那条链相同，二面多强调 **安全门禁**：评测含安全项，不过不能注册。

## 3. 十分钟方案题（二面高概率）

题：给公司「内部知识问答 / AIGC 助手」做应用层安全方案。

按资产 → 威胁 → 控制 → 验证讲，最后给 90 天优先级。

**资产：** 语料与 RAG、基座与 ckpt、推理 API、工具、密钥、日志、生成内容。  
**威胁：** 脏数据入库、越权训练、权重调包、越权问答、提示注入调工具、泄漏、接口滥用、生成内容不可溯源。  
**控制（按链路）：**  
1. 数据：权限、版本、脱敏。  
2. 训练：任务审计、最小可训参数、ckpt 隔离。  
3. 门禁：能力 + 安全回归再注册。  
4. 推理：网关登录、RAG 先过滤、工具白名单、DLP。  
5. 出口：水印/请求 ID；密钥 KMS。  
6. 日志：训和推分开存，业务员看不了全量原文。  

**优先落地三件（校招说这个像工程师）：**  
1. 推理和数据的租户鉴权（不做则全链路白忙）。  
2. 训练任务挂盘鉴权 + 训后回归门禁。  
3. 工具默认拒绝，开放要人审。  

水印放在第 5 步当加分，不要一上来只讲论文。

| 问 | 答 |
| --- | --- |
| 你测过训练安全吗？ | 测的是自己模型：二次微调、L2 剪枝、量化、音频失真后，主任务和可提取性还在不在。没测过公司级多租户训练平台，但知道 Job 的镜像、命令、挂盘都该审计。 |
| 推理安全呢？ | 推理侧做过前向和归属验证；应用层注入/越权是按威胁分类和验证目标来设计，没有打过线上业务。 |

## 5. 二面可能追问

1. 应用层包不包含模型训练？  
   **包含。** 训练是 AI 应用的生产过程：数据、任务、ckpt、回归都是应用层控制点。

2. 和内容审核有什么差别？  
   审核只看输出。应用层还管谁能训、谁能上线、谁能调工具。

3. 对齐做完还要应用层吗？  
   要。对齐管愿不愿意；应用层管能不能做成（权限、数据、门禁）。

4. 你怎么写一条测试用例（不要攻击步骤）？  
   「训练账号只能挂本项目 PVC；挂其他项目路径应被拒绝，并留审计。」「未注册权重部署应失败。」「RAG 无权限文档不得出现在上下文。」

5. 出了泄漏怎么闭环？  
   定影响面（哪些租户、哪次模型版本）→ 下线或回滚制品 → 修控制 → 授权环境回归 → 归档。不对外散播细节。
