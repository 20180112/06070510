# 应用层安全测试 + 方案设计（结合 AI 安全）

面试官已明确：工作更偏 **应用层面的安全测试和方案设计**，不是固件/逆向主业。  
对你：AI 应用（对话、RAG、Agent、AIGC）就是应用层；传统 App/API 的身份、权限、业务逻辑仍然在，模型只是中间多了一层不可信推理。

一律授权环境。只讲 **测什么、方案怎么挡、你能设计什么**，不讲 payload 和利用步骤。

---

## 0. 应用层指哪一层

一个带大模型的产品，大概是：

```
用户 / App / 小程序
    → 业务网关（登录、限流、租户）
    → AI 编排（提示组装、RAG、Agent 规划）
    → 模型（基座 / 微调）
    → 工具与知识库（检索、代码、下单、查库）
    → 日志与内容审计
```

**应用层安全** = 从网关到编排到工具这一截：谁能调、调什么、数据从哪来、输出能不能外泄、出事后能不能查。  
模型权重里的对齐、水印是加分控制，**不能替代**应用层的鉴权和隔离。

口头：「系统层看 OS/加固；应用层看业务接口和 AI 编排有没有把权限做在代码里。面试官要的是后者的测试和方案。」

## 1. 你下一轮可以认领的清单

每条都是：**测试（验证是否失效）+ 方案（怎么设计控制）**。方案用「控制点在哪一层」说，不要只说「把模型训得更听话」。

### 1.1 身份认证（你是谁）

**测：** 未登录能否打到模型接口；过期 token、别人的 token 能否用；会话固定/注销后是否还能聊。  
**方案：** 模型接口挂在和业务 API 同一套登录之后；密钥、AK 不进前端、不进提示词。  
**你能接：** 密码学里的认证；密钥不能进对话（和水印密钥同一原则）。

### 1.2 鉴权与租户隔离（你能干什么）

**测：** A 用户能不能读到 B 的历史对话、知识库、工具结果；普通角色能不能调管理员工具。  
**方案：** 租户 ID 在服务端强制注入检索和工具，不靠模型「请只查当前用户」。RBAC：工具按角色白名单。  
**口头：** 「认证过了不等于能调转账工具。鉴权做在网关和工具适配器上。」

### 1.3 业务逻辑（AI 只是入口）

**测：** 能否跳步骤（没审核就执行）；金额、收件人、权限参数会不会被对话改掉；重复提交。  
**方案：** 敏感动作走原有业务工作流（审核、限额、幂等），Agent 只能发起申请，不能直接改账本。  
这是传统应用层，AI 产品同样要测。

### 1.4 提示注入（应用层最常问的 AI 项）

**测：** 用户话、网页、邮件、知识库文档会不会覆盖系统策略、骗出系统提示、诱使乱调工具。直注和间注都要列成验证项。  
**方案：**  
- 系统指令、用户输入、检索片段、工具返回 **分槽**，检索内容当数据不当指令；  
- 工具调用二次校验（参数 schema + 业务鉴权）；  
- 高风险工具默认关或要人审。  
**不要把「防注入」写成「再 SFT 一次」。** 对齐是辅助，应用层必须挡。

### 1.5 敏感信息泄漏 / 系统提示泄漏

**测：** 追问、翻译、总结会不会带出密钥、内部策略、他人隐私、工具原始返回。  
**方案：** 提示里不放秘密；检索脱敏；输出 DLP/打码；日志分级；禁止模型复述系统提示。  
**你能接：** 水印密钥只在验证方，不能当用户可套的开关。

### 1.6 RAG 知识库污染与越权检索

**测：** 无权限文档会不会被检索进上下文；脏文档会不会改系统行为；回答有没有出处。  
**方案：** 检索前按身份过滤；来源白名单；引用可追溯；冲突时策略优先于文档。  
**方案图：** 用户身份 → 过滤后的索引 → 模型，而不是「先检索全世界再让模型自己判断」。

### 1.7 工具调用 / Agent 越权（方案设计核心）

**测：** 不该出现的工具是否能被规划出来；参数是否被用户话术带偏；失败有没有审计。  
**方案（建议你画这张）：**  
1. 工具注册表：名字、参数、所需角色、是否人审、超时；  
2. 策略引擎：这次会话允许哪些工具（代码，不是提示词）；  
3. 执行沙箱：无网或有限网、超时、禁止任意命令；  
4. 完整日志：谁、何时、哪个工具、参数、结果码。  
**口头：** 「Agent 安全是权限工程。模型可以被说动，工具层必须拦。」

### 1.8 输出滥用与有害内容（应用层护栏）

**测：** 业务禁止类请求是否仍给步骤；过度拒绝是否把正常业务拒掉。  
**方案：** 输入分类 + 输出分类 + 拒绝话术模板；和帮助性一起看（你对齐里的 HHH）。  
SFT/RLHF 是了解；上线还要有可热更新的策略，不必每次都重训。

### 1.9 供应链（提示词、插件、MCP、微调数据、模型文件）

**测：** 第三方插件要哪些权限；提示模板谁能改；权重/LoRA 来源是否可核。  
**方案：** 依赖清单、最小权限、签名校验、可禁用开关、变更评审。  
**你能接：** 训练数据用公开集、要问谁能写进知识库；微调后做安全回归（二次微调那套）。

### 1.10 内容确权与溯源（你的主场，方案里主动提）

**测：** 生成图/文/音离开平台后能否证明来源；微调、压缩、剪枝后信号还在不在。  
**方案：** 生成出口打上可验证水印/日志 ID；对内做归属抽检；密钥 KMS 管，不进提示。  
**测试方法你熟：** 有效性、主任务/听感、L2 结构化剪枝和二次微调后还在不在。  
接到岗位：AIGC 功能的**应用层方案**可以是「生成—分发—争议」闭环，不只是模型论文。

### 1.11 模型提取与接口滥用（应用层限流，不是去偷模型）

**测：** 异常高频、批量下载对话、脚本化遍历接口是否有告警。  
**方案：** 鉴权、配额、WAF/网关限流、异常查询审计、输出可追溯。  
不谈如何做提取实验。

### 1.12 可用性 / 费用打满（无界消耗）

**测：** 超长上下文、无限制工具循环会不会把配额打爆。  
**方案：** 轮次上限、工具次数上限、超时、熔断。这是应用层可用性。

### 1.13 日志、隐私与合规

**测：** 日志里是否有明文密码、完整身份证、系统提示；保留期限；出域。  
**方案：** 最小化采集、打码、访问控制、审计员角色与业务员分离。  
职责 8：秘密不进个人公网助手。

### 1.14 传统 Web/API 仍要覆盖（AI 功能下面还是业务系统）

授权下验证：越权访问对象（IDOR 思路：改资源 ID 看是否鉴权）、未授权 API、文件与回调类入口是否可信。  
只说 **验证鉴权是否在服务端、参数是否白名单**，不说利用方法。  
方案：所有 AI 编排出站的写操作走已有 API 的鉴权，禁止模型直连数据库。

## 2. 方案设计怎么讲（比罗列风险更像工程师）

面试官要方案时，用四段，不要背漏洞名：

1. **资产：** 对话、知识库、工具、模型、密钥、日志。  
2. **威胁：** 谁想越权、泄密、污染知识库、滥用工具、洗掉归属。  
3. **控制：** 网关鉴权、分槽提示、检索过滤、工具白名单+人审、沙箱、DLP、水印、限流、审计。  
4. **验证：** 每条控制有通过/失败标准；上线前回归；修复后再验。

**纵深防御一句：** 对齐管「愿不愿意」；应用层管「能不能做成」；日志管「做了能不能查」。三层都要。

### 2.1 一张可画的基线（建议背）

| 控制点 | 放哪 | 你面试怎么接 |
| --- | --- | --- |
| 登录与租户 | 业务网关 | 网安常识 |
| 提示分槽 | 编排层 | 防注入方案 |
| RAG 过滤 | 检索层 | 权限在查库前 |
| 工具策略 | 适配器 | Agent 核心 |
| 人审 | 高风险写操作 | 业务逻辑 |
| 输出 DLP | 网关后处理 | 防泄漏 |
| 水印/溯源 | 生成出口 | 你的项目 |
| 安全回归 | 发布流水线 | 微调/剪枝评测习惯 |
| 审计日志 | 独立存储 | 闭环 |

### 2.2 用 AI 做安全工作（方案的一部分）

用模型辅助：威胁清单草稿、验证项草稿、日志摘要、报告结构。  
方案里必须写：**人工复核、域内模型、敏感数据不出域。** 对应 JD「AI 用于安全工作」。

## 4. 下一轮 60 秒（对准面试官原话）

面试官你好，上一轮沟通后我理解岗位更偏 **应用层的安全测试和方案设计**。我主线是 AI 安全。应用层我会按信任边界拆：网关身份和租户、提示和知识库谁说了算、Agent 工具鉴权、输出和日志是否泄密、生成内容能否溯源。

测试上：给每类风险定失败标准，在授权环境验证控制是否生效，再给修复建议。方案上：不把安全只写在系统提示里，鉴权做在网关和工具适配器；高风险动作人审；发布前对微调和压缩做安全回归。水印和密码学可以落到 AIGC 出口的确权和密钥管理。终端逆向不是我的主项，应用层威胁模型和验证标准可以马上做。

## 5. 可能被追问

1. 应用层和模型层安全谁更重要？  
   都要。没有鉴权，模型再对齐也会被工具放大。没有对齐，应用层要挡的有害输出会更多。你做方案默认 **应用层强制、模型层增强**。

2. 只做内容安全审核算不算应用层方案？  
   只算输出这一截。缺身份、RAG 隔离、工具权限，Agent 仍然能出事。

3. 你没有测过线上 App，方案会不会空？  
   先出威胁和控制点清单，再和业务确认接口；验证在预发用授权账号打。竞赛里做过端到端演示和评测表，习惯是先设计指标再跑。

4. 让你给公司做一个「AI 助手」安全方案，十分钟讲什么？  
   按第 2 节四段 + 第 2.1 表走一遍，最后给 3 条优先：工具鉴权、RAG 租户过滤、密钥不出提示。
