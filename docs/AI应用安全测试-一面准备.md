## 2. 今晚只记：AI 应用风险（职责 3 / 加分 5）

下面只记 **是什么、测什么、防御看什么**。面试不要讲具体注入语句、越狱模板或利用链。问「你会怎么测」时答：**分类风险 → 设成功/失败标准 → 在授权环境打授权用例 → 看日志和权限是否兜住 → 写影响和修复建议**。

### 2.1 提示注入（Prompt Injection）

**是什么：** 不可信文本（用户输入、网页、邮件、知识库文档）被模型当成「系统指令」执行。  
**直注：** 用户话里改系统目标。**间注：** 模型去读的外部内容里藏指令。  
**测什么：** 系统提示是否仍优先；外部内容是否当数据不当指令；是否会违反安全策略去改目标、泄策略、乱调工具。  
**防御看：** 指令/数据分离、对工具调用二次确认、不可信内容只检索不执行、输出过滤。  
**口头：** 「应用层最常见的是模型分不清谁说了算。测试目标是：不可信内容不能提升权限、不能覆盖系统策略。」

### 2.2 敏感信息泄漏

**是什么：** 系统提示、密钥、内部文档、用户数据、工具返回的隐私字段被说出来或写进日志。  
**测什么：** 追问、总结、翻译、改写会不会带出不该出现的字段；多轮是否把上一轮隐私再吐出。  
**防御看：** 提示里少放秘密、检索脱敏、最小返回、日志打码、拒绝复述系统提示。  
**和你项目：** 水印密钥只能验证方持有，不能当普通用户能套出来的开关——同一类「秘密不能进对话」。

### 2.3 知识库 / 上下文污染（RAG）

**是什么：** 检索进上下文的文档被投毒或误入，模型一本正经引用错知识，或执行文档里的指令（接到间注）。  
**测什么：** 检索来源是否可追溯；低质量/冲突文档会不会压过系统策略；回答是否标注出处。  
**防御看：** 来源白名单、权限隔离（用户只能搜自己有权的库）、引用可核、不可信片段不当指令。

### 2.4 越权工具调用（Agent）

**是什么：** Agent 能调搜索、代码、邮箱、下单、改配置。风险是：不该调的调了、参数被用户话术带偏、一次会话权限过大。  
**测什么：** 有没有鉴权；工具是否最小权限；敏感操作是否人审；失败是否可审计。  
**防御看：** 工具白名单、参数校验、身份绑定、操作确认、完整日志。  
**口头：** 「Agent 安全核心是权限，不是把模型训得更会说。模型可以被说动，工具层必须拦。」

### 2.5 身份与权限滥用

会话身份、租户、角色有没有串。A 用户的检索/工具不能打到 B。测试目标：**鉴权在网关和工具两侧都在，不只靠模型「自觉」**。

### 2.6 Agent 供应链

插件、MCP、第三方工具、提示模板、微调数据、基础模型来源。风险是：引入不可信工具等于引入不可信代码。  
**测什么：** 依赖清单、权限声明、更新渠道、是否可禁用。不要说自己审计过某款 MCP 实现，除非做过。

### 2.7 异常代码执行

Agent 写代码、跑命令、操作文件。测试目标：沙箱、网络隔离、超时、禁止任意命令。你没有做过代码执行利用，只说到 **「执行面必须沙箱化，模型输出不能直接当 root 命令」**。

### 2.8 和 OWASP 怎么对（记名字即可）

面试说到「OWASP LLM / Agentic」用类别，不背编号也行：提示注入、敏感泄漏、供应链、数据投毒、不当输出（有害/越权）、过度授权、系统提示泄漏、向量/检索漏洞、幻觉当事实、无界消耗（成本/拒绝服务）。  
加一句：类别是检查清单，具体用例要按业务授权来设计。

## 3. 对齐（了解，不装实验）

岗位测的是应用，但会问「模型为什么还会听话乱来」。

- **SFT：** 用示范教「该答 / 该拒」。  
- **RLHF：** 奖励模型打分，PPO 一类方法让模型多说高分回复；要同时盯有用和无害。  
- **DPO：** 不用单独训 RM，直接用「更好/更差」对偏好数据更新策略。  
- **HHH：** 有用、无害、诚实会打架。过拒绝也是事故。  
- **推理护栏：** 快，但不是唯一防线；应用层还要权限和日志。

**口头：** 「对齐是了解。我没有完整跑过 RM+PPO。我的实验是在生成模型上加可验证约束，并测后训练之后约束还在不在。对你们来说，对齐解决『愿不愿意遵守策略』，工具权限解决『能不能造成伤害』。」

不要背长公式。被追问：SFT 是示范上的交叉熵；RLHF 用奖励减偏离原模型的约束；DPO 直接拉近赢家、推开输家。

## 4. 后门、模型提取、鲁棒性（红队测试口径）

你的强项。用 **评测语言**，不用攻击教程。

### 4.1 后门 vs 你的水印

| | 后门攻击 | 所有权水印（你做的） |
| --- | --- | --- |
| 目的 | 特定触发下干坏事或留口 | 证明模型/内容归属 |
| 触发 | 攻击者想藏、想泛化 | 验证方持有，协议上要求乱触发无效 |
| 测试 | 有没有意外触发改变行为 | 双条件才激活、单侧不误触发 |

**口头：** 「形式上像后门，目标相反。安全测试里两件事都要：有没有被植入的异常触发，以及我们自己的确权信号会不会被用户套出来。」

### 4.2 你会的鲁棒性测试（授权、对己方模型）

视觉：二次微调、结构化剪枝、量化后，主任务精度和水印检出是否一起变。  
音频：压缩、重采样、滤波、加噪、裁剪后，载荷和听感是否还在。  
共同习惯：**有效性、主任务/质量、攻击后还在不在，三项一起报。**

操作细节（面试常追「你到底怎么微调、怎么剪」）：

- **任务微调：** 加载开源 VLM，设 `requires_grad`，多损失 backward，Adam 用比预训练小的学习率；`eval` + `no_grad` 做验证。音频是冻声码器，只训 adapter。  
- **二次微调：** 带水印模型换干净数据再训若干 epoch，看 WSR 和主任务。轻则去不掉，重则两项一起变。  
- **结构化剪枝：** 按通道或注意力头、按重要性排序、扫比例；剪完看 ΔAcc 和 ΔWSR，一起崩说明绑在有效表示上。不是非结构化把单个权重置零。  
- 超参见作品表，不要临场编 lr。逐步操作和翻车表见讲义 B、C。

接到岗位：上线前给模型做回归——策略还在、能力还在、异常触发没有、去除/微调/压缩后该保留的归属或安全行为还在。

### 4.3 模型提取（概念）

**是什么：** 用大量查询逼近接口行为，得到功能类似的替代模型，伤知识产权和安全策略。  
**测试目标（防御）：** 查询是否限速和审计；输出是否可追溯（水印/指纹）；异常批量访问是否告警；协议是否禁止爬取。  
**你怎么接：** 「我做的是给模型和生成内容加可验证信号，对抗的就是再分发和去除。提取是另一类偷功能，测试上更关心接口滥用和归属证据，我没有做过把别人线上模型偷下来的实验。」

不要讲替代模型怎么训、怎么对齐 logits、怎么选查询集。

### 4.4 数据投毒 / 训练供应链

微调数据、RAG 库、第三方权重都可能被污染。你竞赛里用公开数据集做实验，没有做过投毒利用。口头到：「测试要问数据从哪来、谁能写进知识库、权重校验有没有。」

## 5. 密码学怎么接到本岗

GlobeCom 一作：内容感知 QIM，物理层隐写，格上量化，降失真。证明你能建模、写论文、懂嵌入和提取。  
抗量子竞赛：Frodo 一类密文域载体，关心噪声预算、解密和提取同时成功——**完整性 + 机密性一起成立**。

接到职责 2「身份认证及加密机制验证」（概念，不讲如何破解）：

- 认证：对方是不是声称的身份（口令、证书、密钥）。  
- 机密：信道是不是加密（HTTPS / TLS；IoT 常见还有 MQTT 是否只开了明文）。  
- 完整性：数据有没有被改（MAC、签名）。  
- 密钥：存在哪、会不会进日志或模型上下文。

**口头：** 「IoT 和 App 的加密我没做硬件拆解，但测『机制在不在』我有密码学底子：看协议是否认证、是否明文、密钥是否暴露。抗量子是了解加竞赛，不说自己评估过产线设备。」

BLE / MQTT / HTTPS：一面记定位即可。HTTPS 是 Web/API 传输层；MQTT 是 IoT 发布订阅，要看是否鉴权、是否 TLS；BLE 是近场，要看配对和数据是否明文。没抓过包就说「概念清楚，工具还在补」。

## 7. 移动 / IoT：诚实补概念，不补假经历

**App：** 权限模型（能访问通讯录/相机不等于业务授权）、客户端不可信、关键鉴权在服务端、传输要 HTTPS。逆向、加固绕过：**没做过，知道测试目标是验证加固是否有效，细节入职后在授权环境学。**  
**IoT：** 固件、串口、调试接口是常见攻击面；测试关心调试口是否暴露、默认口令、升级是否签名。UART/JTAG/Binwalk：**名词知道，没有实操。**

被问 Frida/IDA/Burp/Wireshark：Burp/Wireshark 是代理和抓包；IDA/Ghidra 是逆向；Frida 是运行时插桩。**用过 Python/PyTorch 做评测脚本，这些工具是缺口，在学。**

## 8. 可能问的题（先口头）

1. 为什么来做安全测试而不是继续发水印论文？  
   水印已经是「在约束下做可验证、再攻击评测、再写报告」。你们要把同类事做到 App 和 Agent 产品上。我熟模型侧，工程工具可以学。

2. 提示注入和越狱有什么区别？  
   越狱：用户想让**模型**打破安全策略。提示注入：不可信内容想让**应用**把外部文字当指令，常结合工具和数据。都是「谁说了算」，一层在模型，一层在系统集成。

3. RAG 污染怎么测？（不讲投毒做法）  
   看来源隔离、权限、引用、不可信文档会不会改系统行为。设「文档与系统策略冲突时以策略为准」。

4. Agent 最怕什么？  
   过度授权的工具。模型被说动只是诱因，伤害发生在工具执行。测权限、确认、审计。

5. 水印是不是后门？  
   见 4.1。安全测试两边都要做。

6. 模型提取你怎么看？  
   见 4.3。接水印：归属和防再分发；接岗位：接口滥用监控。没做过窃取实验。

7. 你怎么保证测试合规？  
   只打授权范围、授权账号、授权环境；不搬真实用户数据到个人模型；报告走内审；不对外公开未修复漏洞。对应职责 8。

8. 没有移动逆向怎么做职责 1、2？  
   专业是网安，协议和密码学能入门；AI 部分能马上产出测试设计和评测标准。工具链是短板，希望岗上补，不会假装已经会拆机。

9. CVE/CNVD 跟过吗？  
   没有自己的编号。会看公告理解影响面和修复，没有做过公开复现。问到复现：只在授权环境、按厂商说明验证修复是否生效，不扩散细节。

10. 用 AI 写测试脚本放心吗？  
    可起草，必须跑通、看边界、敏感信息不出域。对应任职资格 5。

11. 两次一等奖你做什么？  
    队长。VLM：问题、训练评测、论文叙事；竞赛系统指导。音频：方案、嵌入提取评测、论文。不把队友写的每一行说成自己的。

12. GlobeCom 做什么？  
    物理层隐写，内容感知 QIM，一作。证明密码学和写作。不必在测试岗展开格点公式。

13. 微调具体怎么做的？  
    先分清两种：把水印训进去，是任务微调；换干净数据再训，是二次微调看去不掉。PyTorch，冻哪些层要核对 `requires_grad`，验证必须 `eval`。细节按讲义 B。

14. 剪枝具体怎么做的？  
    结构化，通道或头，重要性排序，扫比例，同时看主任务和水印。音频实验主线是波形失真，不要说成剪枝。细节按讲义 C。

## 9. 不要和「对齐岗 / 平台岗」混

| 对齐岗 | 云原生平台岗 | **本安全测试岗** |
