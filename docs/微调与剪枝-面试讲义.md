# 微调、剪枝、量化：面试细讲（对照你的实验）

给一面用。每节：**是什么 → 你实际怎么操作 → 面试怎么说 → 接到网安工程师的 AI 安全工作**。  
学习率、epoch、剪枝比例用**你表格里的真数**，这里不编。没做过的（QAT、非结构化稀疏加速）直说没做。

主文档口径仍看 [`网络安全工程师-一面准备.md`](网络安全工程师-一面准备.md)。岗位是 **2027届网络安全工程师（J10553）**。

## A. 一次训练循环（微调也是这个）

一步 step 固定顺序，说顺了微调才像做过：

1. DataLoader 取一个 batch  
2. `model.train()`  
3. `optimizer.zero_grad()`（不清会把上一步梯度加进来）  
4. 前向 `output = model(x)`  
5. 算 `loss`（可以多项相加）  
6. `loss.backward()`  
7. 可选：梯度裁剪  
8. `optimizer.step()` 改权重  

验证：`model.eval()` + `torch.no_grad()`。Dropout 关掉，不算梯度。  
口头：「前向看差多少，反向出梯度，优化器改参数。验证必须 eval，否则 Dropout 还开着，分数会抖。」

水印视觉：loss 一般是主任务 CE + 水印 CE + 单侧 KL。  
音频：攻击后 BCE + 干净对比 + 波形一致。  
系数靠验证集扫：主任务掉了加大任务项；误触发加大 KL；音质掉了加大波形项。

## B. 微调怎么操作

### B1. 人话

预训练已经会「通用特征」。微调 = 用你的任务数据继续更新权重，让模型在新目标上好用。  
不是从头训：学习率更小、数据更少、常冻一部分层。

三种常见做法（从贵到省）：

| 做法 | 动哪些参数 | 何时用 | 你有没有 |
| --- | --- | --- | --- |
| 全量微调 | 几乎所有权重 | 数据够、显存够、要上限 | 视觉水印训练可以是全量或大部可训，以你实际为准 |
| 冻主干、训头/投影 | 只动分类头、投影层 | 数据少、显存紧 | 显存不够时冻视觉编码器，只训投影/部分层 |
| LoRA / adapter | 主干冻住，只训很小的附加矩阵 | 保原能力、省显存 | **音频主故事**：冻扩散声码器，只训 adapter + 解码器 |

冻的实现：`param.requires_grad = False`，这些参数不进 Adam，也省优化器状态显存。

### B2. 操作清单（面试按这个数）

1. **选基座**：CLIP / BLIP / SigLIP / LLaVA，或音频扩散声码器。开源权重，不是自己从零预训练。  
2. **定哪些可训**：打印 `requires_grad` 核对，冻错了 loss 不降。  
3. **数据**：公开集（Caltech101、DTD、EuroSAT、OxfordPets；音频 LibriSpeech 等）。训练 `shuffle=True`，验证不要乱序。  
4. **优化器**：Adam / AdamW。微调 lr 通常比从零训小 1～2 个数量级。  
5. **batch**：显存不够就减小 batch，用**梯度累积**（每 N 个小 batch 才 `step` 一次）。  
6. **混合精度 AMP**：省显存；loss 变 NaN 先关掉 AMP 再查。  
7. **多少 epoch**：看验证集，不要只看训练成功率。可早停。  
8. **存盘**：`model + optimizer + step`，才能续训。  
9. **评测**：主任务指标 + 水印检出；不要只报训练集 WSR。

口头 40 秒：「PyTorch 加载开源 VLM，设好冻哪些层，DataLoader 出 batch，多损失 backward，Adam 用微调学习率。验证 eval、无梯度。显存紧就冻编码器、减 batch、半精度或累积梯度。」

### B3. 你项目里其实有两种「微调」

不要混：

**（1）任务微调 = 把水印训进去**  
视觉：在 VLM 上用四条路径监督（干净走原标签，双触发走水印标签，单侧 KL 贴干净分布），这就是在微调行为。  
音频：不是微调整个声码器，是冻生成器、训薄模块，让水印走残差，主听感尽量不动。

**（2）二次微调 = 鲁棒性测试（去除攻击的评测版）**  
已经带水印的模型，换一份**干净数据**再训若干 epoch，看水印还在不在、主任务变成什么样。  
轻量微调常常去不掉；数据多、步数多、学习率大，检测会掉，但主任务也在变——这是**攻击成本**，报的时候两项一起说。

接到网安工作：「业务上线后还会用自家数据再 LoRA。要回归：安全策略、拒答、工具权限相关行为还在不在。我实验里换数据微调后看检出率，是同一类回归。」

### B4. LoRA 再细一句

原权重 W 冻住，只训两个小矩阵，乘起来当成 ΔW，秩 r 很小。显存主要省在优化器状态。  
QLoRA 是基座再量化，你没做就说没做。  
去除攻击也可以是「干净数据上 LoRA 再训」。若水印只趴在很小的低秩方向上，可能更容易被洗；全参里信号和主表示绑得紧，去掉的代价是主任务也变。按你真实设定说「我做的是全参还是 LoRA 水印」。

### B5. 微调常见翻车

| 现象 | 先查 |
| --- | --- |
| loss 不降 | 冻错层、lr 太小、标签接错、忘了 `train()` |
| loss 变 NaN | lr 太大、AMP、梯度爆炸 → 降 lr、clip |
| 训练很好验证很差 | 过拟合；水印只记着训练触发器 |
| 验证脚本分数怪 | 忘了 `eval()` |
| 显存爆 | 减 batch、冻层、累积、短序列 |

**过拟合：** 训练损失低、验证损失高 → 早停、少训、正则。  
**欠拟合：** 两边都高 → 多训、少冻一点、检查损失。  
水印特有：训练集 WSR 很高，换数据微调后掉光 → 没绑到稳定行为上。

## C. 剪枝怎么操作

### C1. 人话

剪枝 = 删掉「不那么重要」的参数，模型变小、算得少。部署、端侧、降成本会用。  
对你：它是**鲁棒性测试**——剪完以后主任务和水印是不是还在。

两类：

| | 非结构化 | 结构化（你做的） |
| --- | --- | --- |
| 怎么剪 | 单个权重置零，稀疏矩阵 | 整通道、整滤波器、整个注意力头、整层拿掉 |
| 硬件 | 不稀疏加速很难变快 | 真正少算、少存，部署更常见 |
| 面试 | 知道即可 | **要能讲操作** |

### C2. 操作步骤（结构化，按这个说）

1. **选粒度**  
   CNN：输出通道 / 卷积核。Transformer：注意力头、FFN 隐层通道、偶尔整层。你按通道或头剪，以实验为准。  

2. **打分：谁该被剪（你这边按 L2）**  
   每个通道 / 滤波器把里面所有权重拿来算 **L2 范数**（平方和再开方）。范数大 = 这个通道能量大、更重要；**范数小的先剪掉**。  
   和 L1 的差别：L1 是绝对值相加；L2 对特别大的权重更敏感，一个通道里只要有几个很大的数，L2 会把它排得更靠前、更不容易被剪。  
   别和 CLIP 里「把特征向量做 L2 归一化再算余弦」搞混：那是表征归一化，不是剪枝。  
   面试：「结构化剪枝，重要性用通道权重的 L2 范数，从小到大剪。比例按作品表。没做随机剪对照就不要编。」

3. **执行**  
   结构化：从模块里删掉对应通道，下一层输入维也要一起改，否则对不上。  
   非结构化：mask 置零，参数量表面上还在。那是按单个权重绝对值剪，你做的不是这个。  

4. **剪完要不要再微调**  
   很多流程是 prune → 再在原任务上短微调，让剩下的权重把精度捞回来。  
   你若剪完直接测，就说「我测的是剪完即刻的主任务和水印，没有做很长恢复训练」或「剪完又微调了 N 个 epoch」——必须和实验一致。  

5. **扫比例**  
   10%、30%、50%……比例升高，精度和水印一起看。只报一个比例没有说服力。  

6. **看什么数**  
   - 主任务：准确率掉多少（ΔAcc）  
   - 水印：检出/WSR 掉多少（ΔTPR / ΔWSR）  
   - 听感（若剪的是音频相关模块）：PESQ 等  

**关键判据：** 主任务和水印**一起崩**，说明信号绑在有效通道上，不是外挂一层皮。  
水印没了、精度几乎不掉，说明信号很好剥，确权不稳，对产品安全也是坏事（策略可能也很容易被剪掉）。

### C3. 和注意力头（VLM 加分口述）

Transformer 多头 = 若干组 QKV。剪头 = 丢掉某类「谁看谁」的关系。  
水印若碰巧只趴在两三个头上，剪这几个头会同时伤检出和精度。评测要写清剪的是头还是 FFN 通道。

### C4. 40 秒口头

「我做的是结构化剪枝。对每个通道或滤波器算权重的 L2 范数，范数小的认为贡献小，按比例剪掉，下一层输入维一起改。扫不同剪枝率，同时看主任务掉点和水印检出掉点。两者一起掉，说明水印绑在有用表示上；只掉水印说明可剥离。数字看作品表。不是把单个权重置零的非结构化剪枝，也不是 CLIP 那种 L2 归一化。」

### C5. 接到岗位

上线前若要压缩模型（剪枝/蒸馏/量化），安全回归要包括：拒答是否还在、工具相关行为是否还在、有没有剪出异常触发。  
你的习惯可直接复用：**压缩前后三件事一起测——能力、安全/水印、有没有新的异常行为。**

不要讲怎么用剪枝当攻击去拆别人的线上模型。

## D. 量化（常和剪枝一起问，讲清即可）

**是什么：** 权重量成更少的比特。FP32 → FP16/BF16（训练常用 AMP）→ INT8（推理更省）。  
**PTQ：** 训完再量化，校准一批数据估范围。  
**QAT：** 训练时就模拟量化，一般更准、更贵。你没做 QAT 就说没做。

操作意识：量化后也要跑主任务 + 水印/策略回归。极值激活、小通道容易量化翻车。  
口头：「剪枝是删结构，量化是降精度。我评过量化后行为在不在，不是 TensorRT 部署专家。」

## E. 三条故事不要串错

| 项目 | 训练怎么动参数 | 鲁棒性怎么动模型 |
| --- | --- | --- |
| VLM 水印 | 微调 VLM（可冻编码器） | 换数据二次微调；结构化剪枝；量化 |
| 生成音频水印 | **冻**声码器，只训 adapter/解码器 | 压缩、重采样、滤波、加噪、裁剪（信号失真，不是剪通道） |
| 对齐（了解） | SFT/LoRA 教拒答 | 再微调会不会灾难性遗忘安全行为 |

音频的 MP3、低通 **不是剪枝**。被问「你音频怎么剪枝」：音频主实验是波形失真；结构化剪枝在视觉 VLM 上做。

## F. 自测（口述）

1. `zero_grad` 不做会怎样？  
2. 冻层的代码直觉是什么？为什么省显存？  
3. 任务微调和二次微调差在哪？  
4. 结构化、非结构化剪枝差在哪？你做哪个？重要性用什么？  
5. 为什么剪枝要同时看准确率和 WSR？  
6. 音频冻声码器是为了什么？  
7. LoRA 去除和全参微调去除，直观差别？  

要点：1）梯度累加，更新乱。2）`requires_grad=False`，不进优化器状态。3）前者把水印/任务训进去，后者用干净数据看能不能洗掉。4）单个权重 vs 整通道/头；你做结构化。5）一起掉才说明绑在核心能力上。6）保住生成听感，水印走残差。7）LoRA 只动低秩方向，可能更好洗也可能洗不干净；全参改动大、主任务也容易变。
