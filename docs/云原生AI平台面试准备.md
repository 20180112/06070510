## 2. 今晚优先：训练侧（你最能打）

### 2.1 一次训练任务平台要管什么

用户提交大约包括：镜像、启动命令、GPU 数、CPU/内存、数据/ckpt 路径、环境变量、重启策略。

平台侧：排队 → 调度到有空闲 GPU 的节点 → 起容器 → 挂存储 → 跑 → 日志采集 → ckpt 落盘 → 失败重试或告警。

口头：「我现在是自己在机器上跑；平台要把镜像、卡、数据和日志标准化，并且失败可查。」

### 2.2 分布式训练（会概念）

- **数据并行 DDP：** 每张卡一份完整模型，各吃不同 batch，梯度求平均。最常见。你若只用过 `DataParallel` 就直说 DP，和 DDP 差在：DP 是一张主卡搜集，DDP 各卡对等通信，大规模用 DDP。  
- **张量并行 / 流水并行（Megatron 那类）：** 模型一张卡放不下，把一层矩阵或不同层拆到多卡。预训练用，你没用不展开。  
- **通信：** NCCL、同机 NVLink、跨机 RDMA/以太网。带宽不够则 GPU 在等通信，利用率掉。

### 2.3 训练效率（岗位「解决规模增长」）

利用率低常见原因：DataLoader 慢、小 batch、频繁存盘、通信等待、CPU 预处理跟不上。  
你能举的例子：batch 太大 OOM → 梯度累积；冻层/LoRA 降显存；AMP。  
平台视角：是否给了足够的共享内存、数据是否在本地 SSD 而不是每次从对象存储抠。

### 2.4 Checkpoint

定期存 `model + optimizer + step`，才能断点续训。平台要：写到 NAS/OSS、版本、别和训练抢盘。  
口头：「ckpt 既是恢复点也是产物，要和代码/镜像版本对齐。」

## 3. 推理引擎（算法岗可能浅问，平台岗会问）

训练一次、推理无数次。指标：**延迟（P99）**、**吞吐（QPS）**、**显存**、**并发**。

- **动态 batching：** 把同一时刻的多个请求拼成一个 batch，提高 GPU 利用率，可能略增单个请求等待。  
- **LLM 推理：** 预填充 prefill + 逐 token decode；KV cache 占显存。vLLM 等做分页 KV、连续 batch。你没部署过就说「知道瓶颈在 decode 和 KV，没上过 vLLM 生产」。  
- **CV/多模态：** CNN/VLM 一次前向一张或一小 batch，和 LLM 的自回归不同。你 VLM 推理就是一次 `model(image, text)`。  
- **扩散：** 多步去噪，延迟高，可减步数、蒸馏、TensorRT。你做过扩散前向，没做过引擎优化。

导出：PyTorch → ONNX / TorchScript / TensorRT，量化 INT8。你评过训练侧量化对行为的影响，不是 TensorRT 部署。

## 4. 云原生名词（必须能口头解释）

下面是「面试要能开口」的浓缩版。命令、YAML、Pending 原因、namespace 和 cgroup 的细分见 [K8s 与 Linux 讲义](K8s与Linux基础-面试讲义.md)。

**容器 Docker**  
把代码、Python、CUDA 依赖打成镜像，换机器结果一致。训练任务 = 镜像 + 命令。  
口头：「我本地 conda 能跑，平台上要用镜像，否则 CUDA 对不上。」

**Kubernetes**  
集群操作系统。最小调度单位 **Pod**（一组容器）。  
- Deployment：长期服务（推理）  
- Job / CronJob：跑完就退出（训练）  
- Service：给 Pod 一个稳定入口  
- GPU：Device Plugin 把 nvidia.com/gpu 当成资源，申请 `nvidia.com/gpu: 1`  
- PVC：声明要一块盘，背后可以是 NAS

没搭过集群就说：概念清楚，没有运维过生产 K8s。

**Kubeflow**  
K8s 上的机器学习套件：Notebook、Pipeline、训练 Operator（PyTorchJob）。把「提交一次分布式训练」变成 K8s 自定义资源。

**Argo Workflow**  
K8s 上的工作流：多步骤 DAG（预处理 → 训练 → 评测 → 导出）。失败重试、依赖边。训练平台的「工作流引擎」常是它或类似物。

**调度**  
默认 kube-scheduler 看 CPU/内存/GPU 是否放得下。AI 平台还会考虑：卡型号、拓扑、队列配额、公平性、抢占。利用率低可能是碎片（两台各剩 1 卡，8 卡任务起不来）。

## 5. 存储（JD 写了 OSS / NAS / RBD）

| | 特点 | 典型用途 |
| --- | --- | --- |
| **OSS** 对象存储 | 按对象、便宜、吞吐高、延迟一般 | 数据集、ckpt 归档、镜像层 |
| **NAS** 文件存储 | 多机同时 mount 同一目录 | 训练时多卡读同一份数据 |
| **RBD** 块存储 | 一块虚拟磁盘，性能较好 | 单机数据库、需要块设备时 |
| 本地 SSD | 最快 | 缓存热点数据、shuffle |

痛点：训练若直接扫 OSS，DataLoader 会等网络。平台常：先缓存到本地或 NAS。

## 6. 操作系统 / 网络 / 数据结构（校招会考）

平台岗比算法岗更爱问这些，和手撕 DP 可以并列准备。

**OS：** 进程 vs 线程；虚拟内存；用户态/内核态；文件描述符；为什么 GPU 训练还要很多 CPU（DataLoader）。Linux：`top`/`nvidia-smi`、磁盘满、权限、环境变量。内核加分项了解即可：调度、cgroup 限制 CPU/内存，容器靠这个隔离。不要装内核开发。人话和命令见讲义 **A 节**。

**网络：** TCP vs UDP；HTTP；训练梯度同步要高带宽低延迟；推理是客户端到网关到 Pod。端口、防火墙导致连不上是常见题。

**数据结构 / 手撕：** 哈希、链表、栈队列、二叉树；DP 和回溯按已有模板。Golang 不熟就用 Python 写，说明主力 Python。

**Golang：** 平台后端常用。会 `Hello`、goroutine 是加分。面试用 Python 写算法一般可接受，主动说在学 Go。
