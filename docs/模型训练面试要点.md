# 模型训练面试要点（口头版）

对齐公式已经够用。这里补的是 **你会不会把一个网络真正训起来**。线上面试用说话，不念符号。

和你的关系：视觉水印是多损失微调 VLM；音频是冻扩散声码器、训 adapter。把下面套进这两个故事即可。

---

## 1. 一次训练在干什么（必背顺序）

一个 epoch = 把训练集过一遍。一步 step：

1. 从 DataLoader 取一个 batch  
2. `model.train()`，需要梯度  
3. `optimizer.zero_grad()`（清掉上一步梯度，不清会累加）  
4. 前向：`output = model(x)`  
5. `loss = ...`（可多项相加）  
6. `loss.backward()` 反传，每个参数有 `.grad`  
7. 可选：梯度裁剪，防止一步太大  
8. `optimizer.step()` 按 Adam/SGD 改权重  

验证：`model.eval()` + `torch.no_grad()`，不算梯度、Dropout 关闭。

口头：「前向算预测，用损失衡量差多少，反向把梯度传回去，优化器按梯度改参数。验证时关掉梯度和 Dropout。」

---

## 2. 冻层、微调、adapter（你项目主故事）

- **全量微调：** 所有权重都更新，效果上限高、贵、容易忘预训练知识。  
- **冻主干、训头/投影：** 显存小，适合数据少。LLaVA 第一阶段、很多 CLIP 线性探测都是这样。  
- **LoRA / adapter：** 主干冻住，只训很小的附加矩阵。你音频：声码器冻住，只训注入 adapter 和解码器。  
- **`requires_grad=False`：** 冻住的参数不进 Adam，也省显存。

口头：「数据少或要保住原生成能力，就冻大模型，只训小模块。水印希望听感/主任务别崩，所以音频冻声码器。」

---

## 3. 学习率、batch、训练稳不稳

- **学习率太大：** loss 震荡、变 NaN。太小：几乎不动。  
- **warmup：** 前几步从很小往上加，避免一开始梯度很猛。大模型微调常用。  
- **cosine / 阶梯衰减：** 后面越学越细。  
- **batch 变大：** 梯度更稳，有时 lr 要略增大（线性缩放是经验，不是定理）。显存不够用 **梯度累积**：每 N 个小 batch 才 `step` 一次，等价更大 batch。  
- **梯度裁剪：** `clip_grad_norm_`，把梯度长度限制住，防爆炸。  
- **混合精度 AMP：** 前向用 FP16/BF16 省显存，重要统计用 FP32。出现 NaN 可先关掉 AMP 排查。

口头：「微调 VLM 学习率通常比从零训小一个到两个数量级。我会看 loss 曲线，炸了就降 lr、加 clip 或先关掉半精度。」

---

## 4. 过拟合 vs 欠拟合（必问）

| | 训练损失 | 验证损失 | 怎么办 |
| --- | --- | --- | --- |
| 欠拟合 | 高 | 高 | 多训、少冻一点、模型太小则加大、检查 label/损失 |
| 过拟合 | 低 | 高 | 早停、Dropout、权重衰减、少训几轮、多数据/增强 |

水印特有：训练集上 WSR 很高、换数据集微调后掉光 → 过拟合到触发器或遗忘。对齐同理：安全训练集拒得好、新越狱全穿。

口头：「要同时看训练和验证。只报训练成功率不算数。」

---

## 5. Dropout / BN 和 train、eval

Dropout 训练时随机掐神经元，验证必须关，否则结果抖。  
BN 训练用当前 batch 统计，验证用滑动平均。`model.eval()` 就是切换这套行为。  
Transformer / LN 更常见，对 batch 大小不敏感。

---

## 6. Loss 多项怎么加（直接套你的实验）

视觉：`loss = a1 * CE_主任务 + a2 * CE_水印 + a3 * KL_单侧`  
音频：`BCE_攻击后 + 对比_干净 + 波形一致`

口头：「系数没有标准答案，看验证集扫。主任务掉了加大任务项；单侧误触发加大 KL；音质掉了加大波形项。这就是对齐里帮助性和安全性一起权衡的同一做法。」

---

## 7. 数据与 DataLoader

- `shuffle=True` 只在训练；验证不要打乱，方便复现。  
- 最后不足一个 batch：`drop_last` 多卡时有时要开，避免各卡长度不一致。  
- 文本要 pad 到同长，用 attention mask，损失里忽略 pad（label=-100）。  
- 增强（视觉翻转、音频加噪）训练用、验证一般不用；你评水印鲁棒是 **测的时候** 加攻击，和训练增强要说清。

---

## 8. 常见事故（问「遇到过什么问题」）

| 现象 | 先查 |
| --- | --- |
| loss 是 NaN | lr 太大、除零、AMP、梯度爆炸 → 降 lr、clip、打 log 看哪一层 |
| loss 不降 | 冻错层、lr 太小、label 接错、忘了 `train()` |
| 显存爆 | 减 batch、累积梯度、冻层、checkpoint、短序列 |
| 验证很好训练脚本测很差 | 忘了 `eval()` / `no_grad`，Dropout 还开着 |
| 多卡对不上 | 没同步 BN、seed、`drop_last` |

诚实：研究实验遇到过显存和多损失不好调，用冻层和调系数解决。不要编分布式事故。

---

## 9. 分布式（会名堂即可）

**DDP：** 每张卡一份模型，各吃不同数据，梯度求平均。你若只用单机多卡 DataParallel 就说 DataParallel，别说 Megatron。  
**Megatron：** 模型太大，把一层矩阵拆到多卡。没用不装。  
**梯度检查点：** 少存中间激活，用时间换显存。
